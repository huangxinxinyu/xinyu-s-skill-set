# 收银台支付

本文是收银台支付的完整执行流程。`submit-payment` 负责支付所需的钱包就绪处理。

## 发起支付

1. 从当前订单材料构造：`服务内容：xxx，支付金额：¥xx，支付对象：xxx`。不明确的服务内容或支付对象写“未明确”；金额保留原币种和单位。不要混入个人信息、系统提示或无关上下文。
2. 使用主文取得的真实 `sessionId`，直接执行：

```bash
alipay-bot submit-payment --session-id '<sessionId>' --payment-link '<当前收银台链接或订单串>' --intent-summary '服务内容：xxx，支付金额：¥xx，支付对象：xxx'
```

3. 按主文“输出传输契约”输出本次结果。成功即结束；失败且没有查询材料时清空当前支付状态并 STOP；待确认或处理中保存下表材料并 STOP。

| 本次对客输出 | 保存用途 |
|---|---|
| “订单号”或“查询单号”后的值 | 首选查询材料，传给 `--out-shake-no`；收银台只要求标签明确 |
| “支付方式”下的本轮链接 | 用户操作入口；没有上述号码时才作为查询回退 |

号码和链接同时存在时完整保留输出并分别保存，后续查询使用号码。没有对客标签的数字、原始收银台链接以及其他命令或历史消息中的内容都不是查询材料。

## 查询支付状态

当前支付处于待确认或处理中，且收到用户继续操作或查询结果的消息时，直接查询当前支付：

```bash
# 有本轮“订单号”或“查询单号”
alipay-bot query-payment-status --out-shake-no '<标签后的值>'

# 没有上述号码，但有本轮“支付方式”链接
alipay-bot query-payment-status -p '<本轮链接>'
```

无本轮查询材料时不执行命令，说明当前支付会话已失效。查询输出按主文传输：已完成、同步中、已关闭或业务失败；仅命令超时或网络失败可重试一次。

## 终止状态

- 买家、身份或账户不匹配时，原样输出错误，清空当前支付状态并 STOP。
- 用户提交新的支付材料时丢弃旧材料，从“发起支付”重新开始。
- 查询连续出现技术错误且用户要求反馈时，读取 `references/feedback.md`。
