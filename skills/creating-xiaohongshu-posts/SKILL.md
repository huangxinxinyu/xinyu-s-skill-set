# 小红书内容创作

把用户的原始素材整理成一篇自然、具体、适合小红书阅读的内容。内容判断是核心；MCP 只是最后的发布手段。

## 创作流程

1. 从素材中提取四件事：写给谁、读者看完得到什么、有哪些可信细节、用户希望产生什么行动。信息足够时直接写，不为不影响成稿的小问题打断用户。
2. 选择最贴近素材的帖子类型：
   - 经历 / 开发记录：起因 → 卡点 → 发现 → 解决 → 现在怎样
   - 教程：结果 → 适用对象 → 步骤 → 易错点 → 可复用结论
   - 产品介绍：具体场景 → 痛点 → 产品如何介入 → 使用示例 → 行动邀请
   - 测评 / 对比：选择标准 → 实际观察 → 适合谁 → 明确结论
   - 清单 / 收藏：筛选标准 → 分组条目 → 一句话点评 → 使用建议
3. 阅读 [content-playbook.md](references/content-playbook.md)，完成标题、封面、正文、配图和标签。优先保留用户自己的措辞与具体细节。
4. 成稿后必须按 [human-tone.md](references/human-tone.md) 做一次去 AI 味复查。只修命中的表达，不为了“像人”强加口语、短句或第一人称。
5. 交付一套可发布内容：主标题、2 个备选标题、封面文案、正文、配图方案、3–6 个标签。用户只要其中一项时，只交付所需部分。

## 轻量优先

- 小红书正文默认写到“足够表达一个观点”就停，通常控制在约 80–220 个中文字；不要为了结构完整而补齐背景、教程、总结或行动号召。
- 截图、照片或对比图已经能说明的信息，不在正文里再解释一遍。正文只保留配图无法替代的经历、判断和必要入口。
- 用户说“轻量”“就这样”“不用讲文字”或给出接近成稿的原话时，优先顺句和删减，不擅自扩写成完整攻略。

## 成稿标准

- 标题不超过 20 个中文字或英文单词；给出明确收益、冲突、发现或结果。
- 前 1–3 行进入真实场景，不用空泛开场。
- 段落短，重点可扫读；用事实、动作、数字和观察替代抽象形容词。
- 只把素材支持的经历、效果和身份写成事实；信息不足时改成建议或可能性。
- 不堆感叹号、emoji、网络热词或整齐得像模板的排比。默认口吻像一个人在分享刚发生的事。
- 正文不手写 `#标签`；发布时把无 `#` 的标签数组交给 MCP。

## 标签实测

真正发布前读取 [tag-observations.md](references/tag-observations.md)。优先选与内容相关且近期实测能出现小红书联想的标签；“未出现联想”只代表一次页面实测结果，“未测试”不能写成失败。平台修复或重新实测后更新日期和状态。

## 发布

当用户明确说“发布、发出去、定时发”时，读取 [mcp-publishing.md](references/mcp-publishing.md) 并调用现有小红书 MCP。若用户只说“写、改、看看”，停在成稿，不调用发布工具。
